# Carve DAW

Synapse Audio Software の **Orion** を参考に作った、Generator 中心・パターン
ベースの DAW。曲を彫刻のように盛ったり削ったりしながら試行錯誤して作るための
道具で、ノートのようにミニマルであることを旨とする。

エンジンは **tracktion_engine**、ドキュメントは独自の ValueTree モデル
(`.carve`, XML)。**Pattern が第一級**なのが要点: tracktion の Clip は配置ごとの
コピーだが、本アプリではパターンを直せば曲中の全配置に反映される (EditSync が
再同期する)。

## 画面

- **メイン**: 左上のロゴがファイルメニュー (Open Recent に直近 10 曲)。
  ツールバーは Orion 流に BPM /
  Pattern・Song / トランスポート / BAR / LOOP (Start・Length) / マスター。
  **Pattern** は各 Generator で最後に選んだパターンを全部同時にループ再生
  (いちばん長いパターンの長さでループし、短いものは繰り返す)、**Song** は
  プレイリストを再生。
  プレイリストの左の行ラベルが Generator の一覧で、最下段の「+ Generator」で
  追加、右クリックでリネーム / 削除
- **Generator ウィンドウ**: 行ラベルのダブルクリックで開く (ミキサーのストリップ名の
  ダブルクリックでも)。**Inst** タブが音源のエディタ、**Pianoroll** タブがパターンの編集。
  808 Drums とドラムキットでは、ロールの鍵盤カラムが音名でなく音色名になり
  (キック / スネア / パッドのサンプル名)、音が入っていないレーンは沈む。
  開いたときもその帯域が映る。上部のピッカーでパターンを選び、
  New / Clone / … (他 Generator へコピー、MIDI 入出力)。Inst タブは表示中の
  エディタの大きさにウィンドウが合う
- **ブラウザ**: プレイリストの左 (⌘B で表示 / 非表示)。上段がお気に入りフォルダ、
  下段がそのフォルダの中身 (サブフォルダとオーディオファイル)。`+` か Finder
  からのフォルダのドロップでお気に入りに登録、★ で今のフォルダを登録 / 解除。
  クリックで試聴 (スピーカーで切替)、ファイルはドラムキットのパッド・
  サンプラーの Inst タブ・プレイリストへドラッグ & ドロップ、ダブルクリックで
  選択中の Generator に読み込む (サンプラーなら差し替え、ドラムキットなら空き
  パッドへ、それ以外なら新しいサンプラーを作る)。お気に入りと開いていた
  フォルダはアプリの設定として残る

## 特徴

- **Generator**: サンプラー・SoundFont・UTAU は「+ Generator」で選ぶとすぐ空のまま
  作られ、その Inst タブが開く (ファイル選択で待たされない)。空の Inst タブには
  Load ボタンと、その種類で最近使ったファイル (UTAU は音源フォルダ) の一覧が
  出て、一覧はクリック 1 回で読み込む。仮の名前 ("Sampler 2" など) のままなら、
  最初に読み込んだファイル (UTAU は音源の名前) が Generator の名前になる。
  種類は **Slate** (内蔵シンセ。エンジンの 4OSC を音源に、専用のパネルを
  かぶせたもの。帯域制限ウェーブテーブル・ボイスごとのフィルタ・パラメータの
  スムージング・指数 AMP エンベロープはエンジン側の作りをそのまま使う。
  パネルは OSC1・OSC2 / FILTER / AMP / OUT の信号経路と、VOICE / LFO の 2 段。
  LFO は行き先 (Pitch・Filter・Width) を選ぶと 4OSC のモジュレーション
  マトリクスに書き込まれる) / **808 Drums** (内蔵ドラムシンセ。ハイハットは
  6 基の矩形波を帯域通過した 808 の回路どおり、CH が OH をチョークする) /
  VST3・AU (プラグイン自身のプリセットも Presets メニューから選べる) /
  サンプラー / ドラムキット (16 パッド、GM 配列) / **SoundFont** (SF2 プレイヤー。
  発音は TinySoundFont。Inst タブでファイルを選ぶかドロップし、プリセットの一覧
  から選ぶ — 選ぶとその音で鳴らして聞かせ、矢印キーで順に聞き比べられる。
  上の欄で名前を絞り込める。バンク 128 は GM のドラムキット。同じ .sf2 を
  使う Generator 同士はサンプルを共有するので、GM 音源 1 本からピアノ・
  ベース・ドラムを別々の Generator に取っても読み込みは 1 回。ファイルは
  サンプラーのサンプルと同じく相対パスでも覚え、見つからなければ Missing
  Media に出る) / **UTAU** (UTAU 音源で歌う。音源のフォルダを選ぶか Inst タブへ
  ドロップする。単独音・連続音・エクストラなど、フォルダ以下の oto.ini は全部
  まとめて読み、Shift_JIS と UTF-8 のどちらでもよい。歌詞はピアノロールで
  ノートをダブルクリックして打ち、Tab / Shift+Tab で前後のノートへ移る。
  かなでもローマ字でもよく、空のノートは「あ」で歌う。前のノートにつながって
  いれば連続音 (「a か」など)、句の頭なら「- か」、なければ単独音を選び、
  prefix.map の音域別の録音も使う。合成は WORLD (OpenUtau の WORLDLINE と
  同系統) でノートごとに裏で行い、子音はノートの頭より先行発声のぶん先に鳴る。
  つながったノートの間は自動のポルタメント。打ち込んだ直後はまだ合成中で
  鳴らないことがある。MIDI キーボードやプレビューは「あ」の録音を音程だけ
  変えて鳴らす。Inst タブの 4 つのつまみで声質を変えられる: Gender (声道の長さ。
  + で太く大人っぽく、- で細く若く。音程は変わらない) / Breath (息の量、50 が
  録音どおり) / Brightness (音色の明るさ) / Modulation (録音の音程の揺れを残す
  量、0 で真っ直ぐ)。つまみを離したときに確定し、Undo でき、そのパートは全部
  合成し直しになる) / オーディオトラック。
  内蔵音源とプラグインのパッチは `.carve` に入る
- **ピアノロール**: Shift 押下中は一時的に選択ツール、⌘ ドラッグで複製
  (ドラッグの途中からでも)、Ctrl 押下中は Snap を無視、選択ノート上の
  右クリックで選択を削除、ペーストはポインタ位置へ、クオンタイズ / スウィング
  (50% がストレート、66% で三連のノリ)
- **プレイリスト**: 配置ごとの長さ (ループ / 切り詰め) と transpose、途中での
  テンポ・拍子変更、オーディオファイルのドラッグ & ドロップ。クリップの
  パターン名をクリックすると差し替えのドロップダウンで、New / Clone から
  その場で新しいパターンも作れる (今と同じ長さなので配置は動かない)。
  ここで選んだパターンはその行の選択になるので、次にペイントで置くクリップも
  それになる
- **ミキサー**: ストリップ名のダブルクリックで Generator ウィンドウ。エフェクトの
  ウィンドウは基本パラメータの一覧だが、絵で見たほうが早いものには上部に図が付く
  (4-Band EQ は応答カーブとバンドごとのハンドル: ドラッグで周波数とゲイン、
  ホイールで Q、ダブルクリックでフラット。Overtop は 3 バンドの入力レベルと、
  ドラッグできる threshold の線)。新しい曲の
  マスターには音割れ防止の **Limiter** が最初から挿さっている (先読み式の
  ブリックウォール。普通のインサートなので、動かすことも外すこともできる)。
  **グループバス**: ストリップの「group」ボタンで New Group を選ぶとバスが
  できて、そのトラックはマスターではなくバスを通る (Live の Group Tracks と
  同じ考え方)。バスにはフェーダー・パン・ミュート・ソロ・エフェクトがあり、
  バスをソロにするとその中身だけが鳴る。バス内のトラックをソロにしても
  バス自体は黙らない。ステム書き出しでは、グループは 1 本のステムになる
  (バスは自分に入ってくるトラックを全部引き込むので、メンバー 1 本だけを
  取り出すことはできない)。
  センド / リターンバス。コンプは別 Generator を**サイドチェイン**元に
  できる。コンプのウィンドウにはリダクション量のメーターが出る。エフェクトは
  tracktion 内蔵 + 自前の **Overtop** (3 バンドのアップワード + ダウンワード
  コンプ。LR4 クロスオーバー、バンドごとのゲイン、Depth で並列ミックス) /
  Distortion / Saturation / **Delay** (テンポ同期の音価、
  量で効くピンポン、L に対する R のオフセット、フィードバック内の低域/高域カット、
  ディレイタイムの LFO、幅) + VST3 / AU
- **オートメーション**: パラメータカーブと LFO モディファイア。どちらも拍基準で
  テンポ変更に追従
- **MIDI 入力と録音**: 接続された MIDI キーボードは選択中の Generator を鳴らす。
  録音ボタン (⌘R) を押すと再生が始まり、弾いた音がそのとき鳴っているパターンに
  重ね書きされる — Pattern モードなら選択中のパターンにループで、Song モードなら
  プレイリストで再生ヘッドの下にあるクリップのパターンに (クリップの transpose は
  差し引かれる)。録音した 1 パスは undo 1 回で消える
- **Capture (後から拾う)**: 録音ボタンを押していなくても、弾いたものは全部
  覚えている。⇧⌘R (トランスポートの Capture ボタン) で、直前のフレーズ (2 小節
  以上の無音で区切った最後のひとまとまり) が選択中の Generator の新しい
  パターン「Capture1…」になり、その場で選択される — Pattern モードならそのまま
  ループし始めるので、重ねて弾くか録音すればよい。再生中に弾いたものは曲の
  小節線に対する位置を保ち、止まっているときに弾いたものは最初の音が頭になる。
  長さは全部の音の頭が入るだけの小節数
- **PC キーボードで弾く**: ⌘K (トランスポートのキーボードボタン) で、MIDI
  キーボードがなくても弾ける。A〜; が白鍵、W/E/T/Y/U/O/P が黒鍵、Z/X で
  オクターブ。A はふつう C4、ドラムの Generator ではキック (C2)。入っている間は
  それらの文字キーは音符なので、ピアノロールの D / E などのツール切り替えは
  効かない (修飾キー付きのショートカットとテキスト入力はそのまま)。録音も
  Capture も MIDI キーボードと同じに効く
- **書き出し** (⌘E): ミックスダウンかステム (Generator ごとに 1 ファイル) を、
  WAV (16/24/32 bit) か Ogg Vorbis (64〜500 kbps) で。範囲は曲全体 / LOOP の
  範囲 / **ゲームループ**。ゲームループは曲頭から LOOP の終わりまでを書き出して
  そこで切り (テールは付けない)、LOOP の頭の位置を Ogg の `LOOPSTART` と
  `LOOPLENGTH` (どちらもサンプル数) に書き込む — RPG ツクール MV/MZ など、
  このコメントでイントロ付きループを再生するゲームエンジン向け。WAV には
  書き込まれないが、値は書き出し画面に出る。LOOP の終わりをまたいで鳴る音の
  余韻はループの頭には回り込まず、そこで切れる
- **設定画面** (⌘, / View メニュー / アップルメニュー): オーディオ出力デバイス・
  サンプルレート・バッファサイズと、使う MIDI 入力デバイスの選択。オーディオ
  入力は出てこない (下記の理由で開かないので)。設定はエンジン側にそのまま
  保存され、適用ボタンの類はない
- **付属コンテンツ**: サンプル曲 3 曲 (File > Open Sample Song / ロゴメニュー) と
  ファクトリードラムキット 9 音。曲は内蔵音源だけで組んであるので外部ファイルを
  参照しない。キットは `content/Drums` に実ファイルとして入り (アプリバンドルの
  `Resources/Content` にコピーされる)、初回起動時にサンプルブラウザの
  お気に入りとして開かれる。音は `scripts/generate-drums.py` で合成したもので、
  ライセンスの要らない自前の素材

すべての編集はモデル (ValueTree) を経由するので、undo・保存・再生中の
リアルタイム反映が一様に効く。

## ビルドと起動

```sh
./run.sh                # ビルドして GUI 起動 (初回は tracktion+JUCE 取得で ~500MB)
./run.sh --asan         # AddressSanitizer ビルドで起動
./run.sh --render ...   # ヘッドレスレンダラ (引数はそのまま渡る)
./run.sh --test         # プロパティテスト (モデル層)
./run.sh --sync-test    # プロパティテスト (エンジンに同期した結果)
```

素の CMake なら `cmake -B build -DCMAKE_BUILD_TYPE=Release && cmake --build build --parallel`。

ロゴを変更するときは `carve.svg` を編集して `python3 scripts/generate-icons.py` を実行する。
アプリ内ロゴ・アプリアイコン・Web 用ロゴと favicon を一括更新する（librsvg が必要。
macOS では `brew install librsvg`）。その後のビルドで macOS の `.icns` にも反映される。

### テスト

Catch2 + RapidCheck による property-based test。既定で有効なので、追加のフラグなしに走る。

```sh
./run.sh --test                       # ビルドして全プロパティを実行
./run.sh --test "[song]"              # タグで絞る (Catch2 の引数はそのまま渡る)
```

プロパティは既定で各 100 ケース。強く回したいときや反例を再現したいときは RapidCheck の環境変数を使う:

```sh
RC_PARAMS="max_success=20000 max_size=200 seed=1" ./run.sh --test
```

テストは 2 つに分かれている。`--test` はモデル層 (エンジンをリンクしないので速い)、
`--sync-test` は**モデルをエンジンに射影した結果**を見る。後者が見張っているのは
「ジェネレータ / リターン / マスターという 3 種類の持ち主を、ある場所では全部
列挙して別の場所では 2 つしか列挙していない」という種類のバグで、実際にそれで
出たバグが 3 件ある (マスターのエフェクトが保存されない・リターンのエフェクト
エディタが即閉じる・マスターの 4 個目のエフェクトが無言で消える)。

不変条件は `sync::findSyncProblems` 1 か所に書いてあり、**Debug ビルドでは同期の
たびに assert される**。つまり Debug で GUI を触っているだけでこの種のバグを
探していることになる。

対象は「モデル層の算術」「ドキュメントの編集操作（undo/redo・XML 往復を含む）」「ピアノロールのノート移動ジェスチャ」。エンジン（tracktion）と GUI コンポーネントは対象外で、テストバイナリは engine をリンクしない。フェッチを避けたいときは `-DCARVE_BUILD_TESTS=OFF`。

エンジンを通す検査は一つだけ、`carve-render --check-note-offs`（`tests/NoteOffPlayback.cpp`）。再生中にノート・クリップ・パターンを消して、鳴っていた音のノートオフが楽器に届くかを、ホスト型オーディオデバイスでブロック単位に回して確かめる。終了コードは鳴りっぱなしになったシナリオ数。

### CLI

```sh
BIN=./build/carve-render_artefacts/Release/carve-render
$BIN --demo demo.wav              # デモ曲をレンダリング
$BIN --sample                     # 付属サンプル曲の一覧
$BIN --sample "Neon Streets" a.wav  # サンプル曲をレンダリング (番号でも可)
$BIN --write-demo demo.carve      # デモ曲を .carve として書き出し
$BIN song.carve out.wav           # .carve をレンダリング
$BIN --scan                       # VST3/AU をスキャン (GUI と設定を共有)
$BIN --plugin-demo <名前> out.wav  # 名前でマッチした VSTi でデモ曲をレンダ
$BIN --rate 48000 song.carve out.wav  # レートを指定 (既定 44100)
$BIN song.carve out.ogg           # 拡張子 .ogg なら Ogg Vorbis (192 kbps)
$BIN --game-loop song.carve bgm.ogg  # 曲頭〜LOOP の終わり、LOOPSTART/LOOPLENGTH 付き
```

`--rate` はどのコマンドにも付けられる。既定は 44100 Hz 固定で、オーディオ
デバイスの設定には左右されない — GUI がデバイスを掴んでいるかどうかで
同じ曲が 44.1k/48k に振れると、md5 比較の回帰チェックが成立しないため。
ブロックサイズも同じ理由で固定 (512)。

## 主なショートカット

各ウィンドウ下部のヘルプバーが「その時できる操作」を表示する。標準的なもの
(Space, ⌘Z, ⌘S, ⌘C/X/V, ⌘スクロールでズーム) は省く。

| キー | 動作 |
|---|---|
| ⌘E | 書き出し (WAV / Ogg、ゲームループ) |
| ⌘R | MIDI 録音の開始 / 停止 (停まっていれば再生も始まる) |
| ⇧⌘R | Capture: 直前に弾いたフレーズを新しいパターンにする |
| ⌘K | PC キーボードで弾く / やめる |
| ⌘, | 設定 (オーディオ出力・MIDI 入力) |
| ⌘B | ブラウザの表示 / 非表示 |
| ⌘D | 複製 (プレイリストではクリップ、Generator ウィンドウではパターン) |
| B / E | ペイント / 選択ツール (プレイリスト)。Shift 押下中は一時的に選択ツールで、ペイント中はクリップの上からでも矩形選択できる |
| D / E | 描画 / 選択ツール (ピアノロール)。Shift 押下中は一時的に選択ツール |
| ⌘ + ノートをドラッグ | 複製して移動 (ドラッグ途中の押下 / 解放でも切り替わる) |
| Ctrl 押下中 | ピアノロール: Snap を一時的に無視 (ドラッグ・描画の途中でも) |
| 右クリック | ピアノロール: 選択中のノート上で選択を削除、それ以外は消しゴム / 行ラベル: Generator のメニュー |
| Alt + ドラッグ | 消しゴム (ピアノロール・プレイリスト) |

## 配布 (署名と公証)

```sh
scripts/release.sh                 # ビルド → 署名 → 公証 → staple → dist/CarveDAW-<version>.dmg
scripts/release.sh --no-notarize   # 署名だけ試す
```

必要なものは Developer ID Application 証明書 (Apple Developer Program) と、
`xcrun notarytool store-credentials carve-notary ...` で保存した公証用の資格情報。
手順はスクリプト冒頭のコメントにある。Hardened Runtime で動かすので、他社の
AU / VST3 を読み込むための `disable-library-validation` だけを
`scripts/Carve.entitlements` で許可している。

## 実装メモ

- **プラグインスキャンは子プロセス**で走る。読み込みで落ちるプラグインが
  あってもアプリは巻き添えにならず、ブラックリスト入りして続行する
- **CLI レンダラーは決定的**: 同一曲のレンダリングはビット一致する
  (発振位相の乱数シードを固定する自前パッチ `patches/` + 単一スレッド実行
  + サンプルレートとブロックサイズをデバイスから切り離して固定)。
  GUI の再生と書き出しはマルチスレッドのまま
- **書き出しは手前から始めて頭を捨てる**: tracktion のレンダラは、グラフに
  遅延 (マスターの Limiter の先読みなど) があると最初のブロックだけ音を
  さらに遅延分遅らせて出し、次のブロックで正しい位置へ飛ぶ。曲頭で鳴る音が
  無音 → 遅れた音 → クリックになる (Renderer::Parameters に回避手段は無く、
  上流の develop も同じ)。そこで CLI もエクスポート画面も、書き出し範囲を
  0.5 秒以上 (ブロック単位) 手前から一時ファイルへレンダリングし、その分を
  削って書き出し先へ移す (`src/sync/RenderPreroll.h`)。遅延の無い曲の結果は
  ビット単位で変わらない
- オーディオクリップは `start` が拍 (音楽的)、`length`/`offset` が秒 (物理的)。
  テンポ変更で位置は動くが、音は伸び縮みしない

### オーディオ入力を開かない理由 (MIDI 入力は開く)

MIDI 録音はするが、オーディオは録音しない。`src/EngineSetup.h` はオーディオ入力を
開かないままにしてある (`shouldOpenAudioInputByDefault() == false`)。設定画面の
オーディオ選択も入力チャンネル 0 で作ってあるので、ここからも開かない。MIDI 入力は
別のドライバなのでこの話とは無関係で、`MidiInputController` が初めて見た物理 MIDI
入力を 1 度だけ有効にし、以後は設定画面のチェックに従う。

オーディオ入力を開かないのは、JUCE 8.0.6 の CoreAudio バックエンドにある
境界外書き込みを避けるためでもある:

`CoreAudioInternal::reopen()` はデインターリーブ用 temp バッファをデバイスの
実ブロックサイズで確保した後、`bufferSize` を要求値に上書きするが再確保しない。
要求サイズを受け付けないデバイス (例: Bluetooth ヘッドセットの 16kHz/320 フレーム
入力に 512 を要求) があると、コールバックがバッファを溢れてヒープを壊す。
既定の入出力が別デバイスだと JUCE が AudioIODeviceCombiner を作るため踏みやすい。

オーディオ入力を開くように変える場合は、`getAvailableBufferSizes()` から要求サイズを
選ぶか、JUCE 側にパッチを当てること。
